01

The three traps.

One field is silently ignored, one only errors at exec time, one template syntax works only in stored workflows — three ways to lose an afternoon.
Trap 01 Silently ignored

web3Connection, not integrationId.

The most dangerous kind of doc gap: the wrong field is accepted. Set integrationId to route the signing wallet and the API validates it, saves it, and then ignores it entirely — your write goes out on whatever wallet the org policy resolves. The real routing key is web3Connection (accepts "default", "eoa", or "safe:<id>").
You'll try { // accepted → silently ignored "integrationId": "int_your-keeper" }
Actually routes the wallet { "web3Connection": "default" // or "eoa", or "safe:<safeWalletId>" }
Found: no error, wrong wallet Fixed in both KH doc pages
Trap 02 Runtime "Invalid JSON"

functionArgs is a JSON string.

The docs example shows an array. The runtime wants a stringified JSON array. Pass the raw array and it accepts, stores, then throws Invalid function arguments JSON at execution — half an hour after your last save.
You'll try { "functionArgs": [ "{{@trigger.body.depositId}}" ] }
Actually works { "functionArgs": "[\"{{@trigger-1:HTTP.depositId}}\"]" }
Found: at run, not create Fixed in docs/api/workflows.md
Trap 03 Template resolver misses

Trigger templates need stored syntax.

The intuitive template — {{@trigger.body.x}} — silently resolves to nothing. Stored HTTP triggers use a slot-scoped path: {{@trigger-1:HTTP.x}}. And the POST body must be wrapped under input.
You'll try // template {{@trigger.body.depositId}} // POST body { "depositId": "0x…" }
Actually works // template {{@trigger-1:HTTP.depositId}} // POST body { "input": { "depositId": "0x…" } }
Found: reading OSS source Fixed in docs/api/workflows.md

03

Field-name map.

The dashboard labels don't match the API fields. This is the mapping every integrator needs — now shipped in the docs.
UI label (dashboard)
API field (workflow body)
Gotcha
Function
abiFunction
Canonical. API rejects function and method; functionName works as an undocumented legacy alias.
Function Arguments
functionArgs
Must be a JSON-encoded string, not a raw array. Errors surface at exec, not create.
Contract ABI
abi
Also a JSON-encoded string. Only the specific fragment KH will call is required.
Web3 Connection
web3Connection
Sender routing: "default" (org policy), "eoa", or "safe:<id>". The wallet is your org's Turnkey wallet, resolved automatically. integrationId looks like the right field but is silently ignored.
Contract
contractAddress
Only one that maps 1:1 with what you'd guess.
Trigger payload
{{@trigger-1:HTTP.x}}
Not {{@trigger.body.x}}. And your POST body must wrap fields under input.
